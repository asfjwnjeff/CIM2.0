# CIM2.0 客户主数据平台架构设计 V2（务实版）

> 基于：客户主数据盘点表（265字段）+ 设计文档 + 业界调研
> 核心原则：**主数据管理平台为主，产业链种子埋下去，逐步演进**

---

## 一、主数据域全景（基于盘点表的完整分类）

从盘点表 265 个字段中识别出 **10 个主数据域**。首期聚焦核心域，其余预留数据结构。

```
客户主数据管理平台 (CIM)
│
├── ① 客户档案         ← 保持不变（现有 customers 表）
│   ├── 基础身份
│   ├── 经营管理（等级/行业/服务产品等）
│   └── 产业链定位      ★ 新增：产业链层级 + 产业链角色（下拉框）
│
├── ② 主体管理         ← 保持不变（现有 entities 三级）
│   ├── 签约主体
│   ├── 服务主体
│   └── 结算主体
│
├── ③ 组织架构         ← ★ 新增域：客户的组织结构
│   ├── 集团-子公司关系
│   ├── 部门/事业部
│   └── 关联企业
│
├── ④ 地址主数据       ← 独立一级菜单（已实现）
│   ├── 收发货方
│   ├── 地址站点
│   ├── 地址用途
│   └── 地址联系人
│
├── ⑤ 联系人管理       ← 独立管理
│   ├── 客户联系人
│   ├── 商务/财务/关务联系人
│   └── 现场联系人（地址级）
│
├── ⑥ 合同与资质       ← 后续建设
│   ├── 合同信息
│   ├── 业务资质/报关资质
│   └── 授权文件/附件
│
├── ⑦ 财务与结算       ← 后续建设
│   ├── 开票信息/银行账户
│   ├── 账期/授信/风控等级
│   └── 结算币种
│
├── ⑧ 产业链关系       ← ★ 新增域：express chain relationships（结构化种子）
│   ├── 供应关系（上游→下游）
│   ├── 代工关系
│   └── 经销关系
│
├── ⑨ 地址作业属性     ← 后续扩展
│   ├── 运输要求
│   ├── 仓储要求
│   ├── 关务/监管属性
│   └── 半导体特殊要求
│
└── ⑩ 数据治理         ← 贯穿全平台
    ├── 编码规则（已实现）
    ├── 版本追溯（已实现）
    ├── 字典管理
    └── 同步状态
```

## 二、菜单结构（务实版）

**核心原则**：保留现有「客户管理」和「主体管理」名称，不做合并；只新增必要入口。

```
工作台                       ← 现有
─────────────────────────────────
客户管理                     ← 保持不变
  └── 详情Tab: [基本信息] [业务档案] [★产业链定位] [组织架构] [联系人] [地址与收发货]
─────────────────────────────────
主体管理                     ← 保持不变
  ├── 服务主体               ← 已有，下挂地址
  ├── 签约主体
  └── 结算主体
─────────────────────────────────
地址主数据                   ← ★ 独立一级菜单（从服务主体深层嵌套提升）
  ├── 全局地址列表           ← 跨客户/主体的统一地址视图
  ├── 收发货方管理
  └── 地址站点管理
─────────────────────────────────
联系人管理                   ← ★ 独立一级菜单
  └── 全局联系人列表          ← 跨客户的联系人视图
─────────────────────────────────
业务管理
  ├── 客户跟进
  ├── 商机管理
  ├── 售前报价
  └── 风控审批
─────────────────────────────────
结算管理
  ├── 账单主体规则
  └── 账单拆分字段
─────────────────────────────────
数据治理                     ← ★ 新增
  ├── 编码规则配置
  ├── 字典管理
  └── 同步监控
─────────────────────────────────
系统管理
  ├── 用户/角色/权限
  ├── 接口管理
  └── 审计日志
```

## 三、Phase 2 实施清单（务实版）

### P0：地址主数据独立（改动最小，价值最大）

| 事项 | 说明 |
|------|------|
| 地址主数据提升为一级菜单 | 从 `/entities/service/[id]/...` 提升到 `/addresses` |
| 全局地址列表页 | 跨所有客户/主体/收发货方的统一地址视图 |
| 现有功能全部保留 | 服务主体详情页中的地址 Tab 也保留，作为快捷入口 |

### P1：主数据域补齐（搭框架，埋种子）

| 域 | 事项 | 改动量 |
|----|------|--------|
| **产业链定位** | 客户表新增「产业链层级」(上游/中游/下游) + 「产业链角色」(设备供应商/晶圆厂/分销商等) 两个下拉字段 | 小：2个字段 + 客户编辑表单加一个卡片 |
| **组织架构** | 新建 `customer_org_structure` 表，记录客户的集团-子公司-部门层级关系 | 中：1个新表 + API + 客户详情页加「组织架构」Tab |
| **联系人独立** | 现有 contacts 表扩展 `contact_type` 字段（客户联系人/商务/财务/关务/现场），全局联系人列表页 | 小：1个字段 + 1个列表页 |

### P2：产业链关系结构化（为以后图谱打基础）

| 事项 | 说明 |
|------|------|
| `chain_relationship` 表 | from_customer_id → to_customer_id + relation_type(供应/代工/经销) + direction |
| 客户详情页「关联企业」Tab | 替代现有的 JSON 字段，列表展示关联企业 + 关系类型 |
| 不做可视化 | 先存数据，等积累够了再做产业链图谱页 |

## 四、Phase 2 关键数据模型

### 4.1 新增表（最小集）

```
-- 产业链定位（扩展客户表，2个新字段）
ALTER TABLE customers ADD COLUMN chain_level TEXT;        -- upstream/midstream/downstream
ALTER TABLE customers ADD COLUMN chain_role TEXT;         -- equipment_supplier/foundry/osat/...

-- 组织架构
customer_org_structure (
  id TEXT PK,
  customer_id TEXT NOT NULL,      -- 所属客户
  parent_id TEXT,                 -- 父节点（自引用，根节点为 NULL）
  org_name TEXT NOT NULL,         -- 组织名称（如"华力集成电路制造部"）
  org_type TEXT,                  -- 类型：集团/子公司/事业部/部门/工厂
  level INTEGER,                  -- 层级深度
  status TEXT DEFAULT 'active',
  created_at TEXT, updated_at TEXT
)

-- 联系人类型扩展
ALTER TABLE contacts ADD COLUMN contact_type TEXT;  -- customer/business/finance/customs/warehouse/transport/site
ALTER TABLE contacts ADD COLUMN party_id TEXT;      -- 关联到主体ID（不仅限于客户ID）
```

### 4.2 后续建表（Phase 3，先定义结构）

```
-- 产业链关系（结构化种子）
chain_relationship (
  id TEXT PK,
  from_customer_id TEXT NOT NULL,
  to_customer_id TEXT NOT NULL,
  relation_type TEXT NOT NULL,     -- supply/manufacturing/distribution/service
  chain_level_from TEXT,            -- 来源端的产业链层级
  chain_level_to TEXT,              -- 目标端的产业链层级
  is_direct BOOLEAN DEFAULT true,
  effective_date TEXT,
  expiry_date TEXT,
  status TEXT DEFAULT 'active',
  created_at TEXT, updated_at TEXT
)
```

## 五、与 V1 版本的关键区别

| | V1（跨越太大） | V2（务实折中） |
|---|---|---|
| 客户/主体 | 合并为"参与方档案" | 保持"客户管理"+"主体管理"不变 |
| 产业链 | 独立一级菜单「产业链全景」 | 作为客户的一个属性字段 + 关系表，先存数据 |
| 菜单 | 大改，新增多个一级入口 | 最小改动：地址独立 + 联系人独立 + 数据治理 |
| 命名 | party（参与方） | 继续用 customer（客户） |
| 节奏 | 一次到位 | 分 P0/P1/P2 三步走 |

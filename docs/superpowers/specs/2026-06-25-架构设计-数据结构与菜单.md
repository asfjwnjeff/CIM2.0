### 2.2 V1 数据模型 — 参与方（Party）中心化

**核心原则**：一个法律实体 = 一条 Party 记录。角色是标签、产业链关系是独立实体。

#### 表：party（参与方统一主表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | TEXT PK | 系统唯一ID |
| party_code | TEXT | CIM 统一编码，格式 `PTY-{国家代码}-{序号}` |
| uscc | TEXT | 统一社会信用代码，全局唯一 |
| legal_name_cn | TEXT | 法定中文全称 |
| legal_name_en | TEXT | 英文全称 |
| short_name_cn | TEXT | 中文简称 |
| short_name_en | TEXT | 英文简称 |
| party_identity_type | TEXT | 参与方类型：企业 / 组织 / 个人 |
| domestic_overseas_flag | TEXT | 境内外标志：境内 / 境外 / 港澳台 |
| legal_representative | TEXT | 法定代表人 |
| established_date | TEXT | 成立日期 |
| registration_country | TEXT | 注册国家/地区 |
| registered_address | TEXT | 注册地址 |
| business_address | TEXT | 营业地址 |
| mailing_address | TEXT | 通信地址 |
| operating_status | TEXT | 经营状态 |
| status | TEXT | 状态：草稿 / 生效 / 停用 / 失效 / 黑名单 |
| source_system | TEXT | 来源系统：cim / cpq / cos |
| legacy_party_code | TEXT | 原系统编码映射 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间 |

#### 表：party_role（参与方角色）

### 2.3 V3 数据模型 — 客商 ⇄ 主体 双向关联

**核心原则**：客商（业务视角）和主体（法律视角）各自独立管理，通过统一社会信用代码（uscc）自动双向关联。产业链关系作为独立表，组织架构和联系人归属客商内部的 Tab 管理。

#### 表：customers（客商档案 · 业务关系视角）

```
┌─────────────────────────────────────────────┐
│                  customers                  │
├─────────────────────────────────────────────┤
│ id               TEXT PK                    │
│ name             TEXT NOT NULL   名称       │
│ customer_code    TEXT            客商编码   │
│ uscc             TEXT     ←───── 统一社会信用代码，与主体关联的桥梁
│ status           TEXT            状态       │
│ level            TEXT            客户等级 K/A/B/C/D
│ industry         TEXT            行业分类   │
│ service_products TEXT (JSON)     服务产品   │
│ ★ chain_level   TEXT            产业链层级 upstream/midstream/downstream
│ ★ chain_role    TEXT            产业链角色 设备供应商/晶圆厂/分销商/...
│ signing_entity_ids   TEXT (JSON) 关联签约主体ID列表
│ service_entity_ids   TEXT (JSON) 关联服务主体ID列表
│ settlement_entity_ids TEXT(JSON) 关联结算主体ID列表
│ responsible_persons  TEXT (JSON) 归属人员
│ progress_status      TEXT        跟进进度
│ source_system        TEXT        来源系统 cim/cpq
│ entity_types         TEXT (JSON) 自身主体类型标签
│ ...（已有字段保留）                    │
│ created_at / updated_at  TEXT             │
└─────────────────────────────────────────────┘
```

#### 表：service_entities / signing_entities / settlement_entities（主体档案 · 法律实体视角）

```
┌─────────────────────────────────────────────┐

│ name             TEXT NOT NULL   主体名称   │

│ establishment_date TEXT          成立日期   │
│ status           TEXT            状态       │
│ address          TEXT            注册地址   │

客商 ⇄ 主体关联逻辑：
  customers.uscc = entities.uscc → 自动匹配

```

## 三、V1 与 V3 关键差异对比

| 维度 | V1 · 产业链平台 | V3 · 务实主数据平台 |
|------|----------------|-------------------|
| 顶层入口 | 参与方档案（Party）统一客户+主体 | 客商管理（Customer）+ 主体管理（Entity）分开 |
| 核心主键 | party_id | customer_id / entity_id 各自独立 |
| 关联方式 | 角色标签 party_role | USCC 自动关联 + 详情页互跳 Tab |
| 产业链 | 独立一级菜单 + 可视化图谱 | 独立一级菜单 + 普通列表页 |
| 组织架构 | party_relationship 自引用 | customer_org_structure 自引用（客商 Tab 内） |
| 联系人 | 独立一级菜单 | 客商详情 Tab 内（contact_type 扩展） |
| 菜单数量 | 9 项 | 8 项 |
| 改动量 | 大（合并现有模块） | 中（保留现有模块，新增独立菜单） |
| 扩展方向 | 产业链平台，突出可视化 | 主数据平台，逐步扩展 |

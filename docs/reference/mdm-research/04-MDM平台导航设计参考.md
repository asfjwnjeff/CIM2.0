> 来源：SAP MDG Fiori、Stibo Systems、Talend MDM、多个 MDM 平台 UI 分析  
> 整理日期：2026-06-24

## 1. 导航层级设计原则

### 1.1 深度控制

```
Level 1（一级）：领域/业务域    例："主数据管理"、"数据治理"、"系统配置"
Level 2（二级）：实体/主题域    例："客户管理"、"物料管理"、"审批工作台"
Level 3（三级）：视图/操作      例："客户列表"、"客户查询"、"新增客户"
        内容区：数据表格、表单、详情页
```

**硬约束**：
- 一级菜单：4-6 个最多
- 二级菜单（每个一级下）：≤6 个
- 三级菜单：超过 7-10 项时使用类别标题分组

### 1.2 推荐一级导航结构（面向 B2B 主数据平台）

| 一级导航 | 二级内容 | 适用角色 |
|----------|---------|----------|
| **工作台** | 仪表盘、我的待办、我的申请、数据概览 | 所有角色 |
| **主数据管理** | 主体档案、地址主数据、联系人管理 | 数据管家/专员 |
| **业务管理** | 客户跟进、商机、报价、风控审批 | 业务人员 |
| **数据查询** | 全局搜索、高级检索、数据浏览、导出 | 所有角色 |
| **数据治理** | 审批工作台、数据质量监控、匹配去重、变更日志 | 数据管家/审批者 |
| **系统配置** | 用户管理、角色权限、流程配置、编码规则 | 系统管理员 |

## 2. 按角色区分导航可见内容

| 角色 | 可见一级导航 | 说明 |
|------|-------------|------|
| 数据请求者（客服） | 主数据查询、主数据申请、我的申请 | 日常增删改查 |
| 数据管家 | 仪表盘、我的任务、匹配队列、搜索 | 治理审核 |
| 数据所有者 | 数据质量、治理策略、数据血缘、报表 | 管理决策 |
| 系统管理员 | 系统配置、安全管理、菜单布局、用户管理 | 平台运维 |

**原则**：不同角色登录后看到的菜单结构不同，无权限项直接不渲染（非置灰）。

## 3. B2B 场景下"法律实体"与"业务角色"的导航处理

### 3.1 核心原则

| 场景 | 导航方式 |
|------|---------|
| 同一实体不同角色间切换 | **Tab 切换**，不离开当前页面 |
| 跨法律实体跳转 | **面包屑**，保持层级路径可见 |
| 层级浏览（母公司/子公司） | **侧边栏树**，快速定位关联实体 |
| 全局查找 | **全局搜索**，支持名称/编号/税号 |

### 3.2 详情页推荐布局

```
┌─────────────────────────────────────────────┐
│ 面包屑：主数据管理 > 主体档案 > 华为技术有限公司 │
├─────────────────────────────────────────────┤
│ [基本信息] [业务档案] [角色与绑定] [收发货与地址] │  ← Tab 切换
│ [联系人] [财务与风控] [版本与同步]              │
├─────────────────────────────────────────────┤
│                                              │
│  法律实体信息（基本信息 Tab）                   │
│  名称 / 统一社会信用代码 / 法人 / 注册地址等     │
│                                              │
│  业务角色标签：                                │
│  [签约主体] [服务主体] [结算主体]               │
│                                              │
│  收发货与地址（收发货与地址 Tab）               │
│  └── 服务主体 A                               │
│      ├── 收发货方 1 → 地址站点 ① / ②          │
│      └── 收发货方 2 → 地址站点 ③              │
└─────────────────────────────────────────────┘
```

### 3.3 SAP MDG Fiori 参考

SAP MDG 的 Fiori Launchpad 结构：

```
Fiori Launchpad
├── 目录（Catalog）= 应用集合
│   └── 业务目录 = 按角色分组的应用
│       ├── 请求者业务目录（新建/查询）
│       └── 审批者业务目录（审批/驳回）
├── 组（Group）= 视觉分组
└── 磁贴（Tile）= 单个应用入口
    ├── Request New Customer（请求新建客户）
    ├── Track My Requests（跟踪我的请求）
    └── Approve Master Data（审批主数据）
```

## 4. 导航设计反模式（需避免）

| 反模式 | 原因 |
|--------|------|
| 级联飞出菜单 | 需要精确鼠标操作，移动端不可用 |
| Tabs + 下拉菜单混合 | 破坏 Tab 隐喻，用户预期不一致 |
| 垂直菜单标签换行 | 单行换行看起来像两个独立命令 |
| 过多顶级菜单（>6） | 导致选择瘫痪 |
| 固定不变的左侧导航 | 与当前页面内容无关的链接浪费空间 |
| 深层嵌套（>3级） | 用户找不到功能入口 |

## 5. 对 CIM2.0 的建议

### 5.1 菜单方案（推荐）

```
工作台           ← 仪表盘、待办、数据概览
主数据管理
  ├── 主体档案    ← 法律实体入口（合并原客户管理+主体管理）
  ├── 地址主数据  ← 全局地址视图（跨主体搜索）
  └── 联系人管理
业务管理
  ├── 客户跟进
  ├── 商机管理
  ├── 售前报价
  └── 风控审批
结算管理
  ├── 账单主体规则
  └── 账单拆分字段
系统管理
  ├── 用户/角色/权限
  ├── 字典/接口
  └── 审计日志
```

### 5.2 搜索驱动导航

- 全局搜索框（Cmd+K）作为最高频导航入口
- 支持按名称、编码、信用代码、地址关键词搜索
- 搜索结果分组显示（主体/地址/联系人）

### 5.3 详情页 Tab 设计

主体详情页按 Tab 分区，每个 Tab 承载一个关注维度：
- 基本信息 → 法律档案属性
- 业务档案 → 行业、等级、服务产品等
- 角色与绑定 → 签约/服务/结算标签 + 关联客户
- 收发货与地址 → 地址主数据完整树
- 联系人 → 客户/商务/财务/现场联系人
- 版本与同步 → 审计日志 + 同步状态

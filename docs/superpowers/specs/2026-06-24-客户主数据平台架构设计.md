## 一、平台核心视角：产业链平台

### 1.1 为什么是"产业链平台"

半导体供应链服务的本质不是"管理客户"，而是**连接产业链上的各个参与方**：

```
上游                    中游                    下游
设备供应商  ──────→  晶圆厂/封测厂  ──────→  终端厂商/分销商
材料供应商            IDM/Fabless             系统集成商
IP/EDA厂商            OSAT/SIP                 消费者品牌
```

公司的业务（关务、仓储、运输、报价计费、订单履约）发生在这些参与方之间的**物流、资金流、信息流**上。平台要管理的不仅是谁是你的客户，更是**他们在产业链的什么位置、和谁有关系、通过什么链条连接**。

### 1.2 产业链视角 vs 传统客户管理

| 传统 CRM | 产业链平台 |
|----------|-----------|
| 客户是一个个孤立记录 | 参与方是链条上的节点 |
| 关注：这个客户值多少钱 | 关注：这个客户在链条的哪个位置、他的上下游是谁 |
| 关系管理靠销售跟进 | 关系是结构化的产业链关系 |
| 销售漏斗驱动 | 产业链洞察驱动（交叉销售、风险传导、链条覆盖） |

## 六、数据模型核心关系

```
party (参与方) —— 一条法律实体只有一条记录
  │
  ├── party_industry_chain (产业链定位)
  │   ├── chain_level: upstream / midstream / downstream
  │   └── chain_role: 设备供应商/材料商/晶圆厂/封测厂/分销商/终端厂商...
  │
  ├── party_role (角色标签，可多选)
  │   ├── 签约主体
  │   ├── 服务主体
  │   └── 结算主体
  │
  ├── chain_relationship (★ 产业链关系，核心新增实体)
  │   ├── from_party_id → to_party_id
  │   ├── relation_type: 供应/采购/代工/经销/服务
  │   ├── chain_direction: upstream → downstream
  │   ├── is_direct: 是否直接关系
  │   └── 可视化链路: A → B → C → D
  │
  ├── business_profile (业务档案，1:1)
  │
  ├── party_relationship (参与方关系，自引用)
  │   └── parent_party_id → party.id（母子公司/集团层级）
  │
  ├── shipper_consignee (收发货方，仅服务主体下有)
  │   └── address_site (地址站点)
  │       ├── address_usage (地址用途)
  │       ├── address_contact (地址联系人)
  │       └── address_version (版本快照)
  │
  └── contacts (联系人，扩展 contact_type)
```

### 产业链关系示例

```
┌──────────────┐   供应设备   ┌──────────────┐   代工晶圆   ┌──────────────┐
│ 应用材料(中国) │ ─────────→ │ 华力集成电路   │ ─────────→ │ 华为终端      │
│ 上游-设备供应商 │           │ 中游-晶圆厂    │           │ 下游-终端厂商  │
│ 角色: 签约+服务 │           │ 角色: 服务主体  │           │ 角色: 签约+结算 │
└──────────────┘            └──────────────┘            └──────────────┘
       │                          │                          │
       │ 我司提供: 货代+关务       │ 我司提供: 仓储+运输       │ 我司提供: 进出口
       ▼                          ▼                          ▼
   [地址站点A]               [地址站点B]               [地址站点C]
   上海浦东仓库               张江工厂月台                深圳保税仓
```

### 为什么产业链关系是核心实体而非 JSON 字段

| JSON 字段方式（现有） | 独立实体方式（目标） |
|-------------------|-------------------|
| related_companies: [...] | chain_relationship 表 |
| 无法查询"谁是A的下游" | SELECT * WHERE from_party_id = A |
| 无法反向追溯"B的上游是谁" | SELECT * WHERE to_party_id = B |
| 无法计算链条深度 | 递归 CTE 遍历整条链 |
| 无法做链条覆盖分析 | 按产业链角色聚合统计 |
| 关系没有时间/状态/来源 | 每条关系有生效日期、失效日期、数据来源 |

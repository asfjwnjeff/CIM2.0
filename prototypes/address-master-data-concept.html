💡 门牌号变更 vs 地址变更：
· 仅改门牌号（如 301→302）→ 不触发重新解析，只更新拼接结果
· 改详细地址（道路级变更）→ 触发重新解析 + 新版本快照
7 地址纠偏反馈闭环：现场发现偏差 → 回传修正 → 全局同步
❌ 当前现状：无留痕、无反馈
客户说地址A → 客服录A → COS传A → TMS司机到现场发现是B
→ 司机自己送到B → 系统还是A → 下次还用A → 循环出错
✅ 新方案：现场纠偏 → 回传CIM → 源头修正
司机发现偏差 → 移动端上报实际地址+GPS → CIM生成纠偏记录
→ 客服核实 → 接受修正 → 地址新版本 → 下游同步 → 永不重复出错

8 传统做法 vs 标签化模型
❌ 传统做法：地址散落各处
存储位置地址类型格式
customers.basicInfo营业地址省/市/区/详细 四个字段
customers.businessInfo注册地址纯文本
customers.invoiceAddress开票地址纯文本
service_entities.address注册地址纯文本
address_sites运输地址结构化 ✓ 但仅运输
⚠️ 问题：同一物理地址在 5 个地方存储，改一处漏一处 → 数据不一致；大部分是纯文本 → 无法解析、无法检索、无版本追溯
✅ 标签化模型：统一地址主数据
存储位置地址类型格式
address_sites注册 + 营业 + 收货 + 开票结构化 ✓
← 4 个标签挂在同一条记录上
address_sites营业 + 通信 + 开票结构化 ✓
address_sites收货 + 发货 + 报关结构化 ✓
address_sites收货 + 退货结构化 ✓
✅ 优势：4 条地址记录覆盖全部 12 种用途标签。地址变更只需改 1 次，所有业务模块自动看到最新值。每条地址都有结构化地理信息 + 版本追溯 + 解析校验。

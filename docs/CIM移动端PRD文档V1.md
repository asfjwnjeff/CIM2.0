## 1. 概述

### 1.1 背景

CIM 2.0 桌面端（Next.js Web 应用）已完整覆盖客户管理、商机管理、跟进记录、售前报价、风控审批、账单拆分等全部业务模块。但实际业务中存在大量**移动办公场景**——审批人出差/会议期间需要快速处理审批、销售人员外出拜访客户时需要现场记录和打卡——桌面端在手机上体验差（228px 固定侧栏、12 列表格布局无法自适应）。

移动端作为桌面端的**移动伴侣**，聚焦高频、碎片化、移动特有的操作场景，以钉钉 H5 微应用形态嵌入现有工作流。

### 1.2 移动端定位与目标

| 定位维度 | 说明 |
|---------|------|
| **产品定位** | CIM 桌面端的移动伴侣，不是替代品 |
| **目标场景** | 碎片化审批、现场打卡、消息触达 |
| **核心价值** | 让审批人和销售在移动场景下能**完成关键操作**，不让流程卡在"等回到电脑前" |
| **不做什么** | 后台配置、复杂数据录入、大表格浏览 |

核心目标：
- 审批待办**主动触达**（钉钉工作通知 + 站内消息双通道）
- 审批操作**快速完成**（一键通过/驳回，附带审批辅助报告）
- 外出拜访**现场记录**（GPS 打卡 + 现场拍照 + AI 听记会议纪要）
- 关键信息**随时可查**（待办概览、消息历史）

### 1.3 与桌面端的关系

```
桌面端（全功能工作站）          移动端（移动伴侣）
┌─────────────────────┐        ┌─────────────────┐
│ 客户管理（完整CRUD）  │        │                 │
│ 商机管理              │        │  待办概览        │
│ 售前报价              │        │  审批中心        │
│ 合同签署              │        │  消息中心        │
│ 账单规则配置          │        │  客户跟进        │
│ 系统管理              │        │  （含打卡+AI听记）│
│ 风控审批 ◄───────────┼────────┤  风控审批        │
│ 客户跟进 ◄───────────┼────────┤  客户跟进        │
│ 数据字典              │        │                 │
└─────────────────────┘        └─────────────────┘
    同一后端 API  ·  同一数据库  ·  同一登录态
```

### 1.4 范围

**包含**：移动首页（待办概览）、审批中心（列表/详情/新建）、消息中心、客户跟进（列表/新建含打卡+AI听记）

**不包含**：客户管理 CRUD、商机管理、售前报价、合同签署、账单规则配置、系统管理、字典管理、审批工作流配置、自动审批规则配置

## 2. 手机端与电脑端分工协作

### 2.1 设计原则

1. **数据同源**：移动端和桌面端共用同一套 API 和数据库，不存在数据孤岛
2. **操作互补**：桌面端做"配置和深度操作"，移动端做"触达和快速响应"
3. **状态一致**：任何一端的状态变更即时反映到另一端（通过 store + API 同步）
4. **场景适配**：移动端 UI 针对单手操作、碎片时间、小屏幕优化

### 2.2 功能分工矩阵

| 功能模块 | 桌面端 | 移动端 | 分工逻辑 |
|---------|:--:|:--:|------|
| **客户管理** | ● 完整CRUD | ○ 仅首页统计 | 桌面录入，移动查看统计 |
| **联系人管理** | ● 完整CRUD | ✕ | 表单过长不适合手机 |
| **商机管理** | ● 完整CRUD | ✕ | 复杂SWOT分析不适合手机 |
| **售前报价** | ● 创建/编辑/发送 | ✕ | 定价需桌面完成 |
| **风控审批-列表** | ● 表格+筛选 | ● 卡片+筛选 | 两端各自适配的视图 |
| **风控审批-新建** | ● 完整表单 | ● 完整表单 | 字段一致（PRD对齐），移动端折叠分区 |
| **风控审批-详情** | ● 详情+3个Tab | ● 详情+Section | 内容一致，移动端堆叠展示 |
| **风控审批-审批操作** | ● 通过/驳回 | ● 通过/驳回 | 功能完全对等 |
| **风控审批-辅助报告** | ● | ● | 同一 `evaluateApprovalRules()` |
| **客户跟进-列表** | ● 表格+分组 | ● 卡片+筛选 | 两端视图适配 |
| **客户跟进-新建** | ● 完整表单 | ● 完整表单 | 字段一致，移动端含打卡+AI听记 |
| **客户跟进-打卡** | ● | ● | GPS定位+拍照，功能一致 |
| **客户跟进-AI听记** | ● | ● | 录音+转写+纪要，功能一致 |
| **审批流程配置** | ● | ✕ | 后台管理，移动端不需要 |
| **自动审批规则** | ● | ✕ | 后台管理，移动端不需要 |
| **消息通知** | ○ Bell铃铛 | ● 完整消息中心 | 移动端为主，桌面端保留铃铛 |
| **系统管理** | ● | ✕ | 后台管理 |

> ● = 完整功能  ○ = 简化功能  ✕ = 不支持

### 2.4 典型协作场景

**场景一：审批流转**

```
1. 客服在桌面端新建风控审批 → 提交
2. 系统评估审批辅助报告，生成审批实例
3. 钉钉推送工作通知给审批人（如：张洁，职能审批）
4. 审批人在手机上收到通知 → 点击 → 跳转移动端审批详情
5. 查看辅助报告 → 确认无误 → 点击「通过」→ 完成
6. 流程流转到下一个审批节点，重复步骤 3-5
```

**场景二：外出拜访**

```
1. 销售人员到客户现场 → 手机打开 CIM → 新建跟进
2. 选择客户 + 跟进方式「上门拜访」→ 点击打卡签到
3. GPS 自动定位 + 拍照 → 打卡信息写入记录
4. 打开 AI 听记 → 开始录音 → 会议全程录音 + 实时转写
5. 会议结束 → 停止录音 → AI 生成摘要/要点/待办/决策
6. 补充跟进内容 → 保存 → 数据即时同步到桌面端
```

## 3. 用户角色（移动端视角）

桌面端 PRD §2 定义了 12 种角色。移动端聚焦其中 3 种核心角色：

| 角色 | 使用模块 | 核心场景 |
|------|---------|---------|
| **审批人**（风控专员/经理/总经理/财务） | 审批中心、消息中心 | 接收钉钉通知 → 查看审批详情+辅助报告 → 通过/驳回 |
| **销售人员**（业务/客服） | 客户跟进、审批中心、首页 | 外出拜访打卡 + AI 听记；查看自己的审批申请进度 |
| **管理员** | 首页 | 查看全公司待办统计概览 |

## 4. 核心业务流程

### 4.1 审批处理流程

```
触发: 钉钉工作通知 或 打开消息中心
  │
  ▼
查看待审批列表（卡片视图）
  │
  ├→ 点击卡片 → 审批详情
  │     │
  │     ├→ 查看基本信息 / 关联信息 / 业务信息 / 合规审核
  │     ├→ 查看审批流程（6节点时间线）
  │     ├→ 查看审批辅助报告（自动规则评估结果）
  │     └→ 查看操作历史
  │
  ├→ 审批中状态:
  │     ├→ [通过] → 节点推进 → 检查是否全部完成
  │     │        → 是: 审批完成 → toast "审批已通过"
  │     │        → 否: 下一节点活跃 → 推送通知给下一位审批人
  │     ├→ [驳回] → 填写驳回理由 → 节点标记 rejected
  │     │        → 审批状态变为"已驳回" → toast "审批已驳回"
  │     └→ [撤回] → 二次确认弹窗 → 所有节点重置 → 变为草稿
  │
  ├→ 草稿状态: [发起审批]
  └→ 已驳回状态: [编辑并重新发起] → 跳转桌面端编辑页
```

### 4.2 现场跟进流程（打卡 + AI 听记）

```
触发: 销售人员到达客户现场
  │
  ▼
新建跟进 → 选择客户 + 跟进类型 + 跟进时间
  │
  ├→ 选择跟进方式「上门拜访」
  │     └→ 显示打卡区域
  │           ├→ [打卡签到] → GPS 定位 + 逆地理编码获取地址
  │           │              → 拍照（FileReader → base64）
  │           │              → 可多次打卡（多条记录）
  │           └→ 已打卡记录时间线（地址+坐标+时间+照片）
  │
  ├→ AI 听记（可选）
  │     └→ AI 听记（始终可见，点击即开始）
  │           ├→ [开始录音] → 计时器开始 → 实时转写
  │           ├→ [暂停] / [继续]
  │           ├→ [停止] → AI 自动生成:
  │           │        ├→ 会议摘要
  │           │        ├→ 关键要点（每行一个）
  │           │        ├→ 待办事项（每行一个）
  │           │        └→ 决策事项（每行一个）
  │           └→ [AI 重新生成] → 重新分析转写文本
  │
  └→ 填写跟进内容 → [保存跟进]
```

### 4.3 消息通知流程

```
触发: 审批流转 / 跟进逾期 / 系统通知
  │
  ▼
┌─────────────────────────────────────────────┐
│              双通道通知                       │
│                                              │
│  ① 钉钉工作通知（主动推送）                    │
│     └→ 点击 → 跳转移动端对应页面               │
│                                              │
│  ② 站内消息中心（被动查看）                     │
│     └→ /mobile/notifications                 │
│          ├→ 筛选: 全部/审批/提醒/系统           │
│          ├→ 点击消息 → 标记已读 + 跳转         │
│          └→ [全部已读] → 二次确认 → 批量标记    │
└─────────────────────────────────────────────┘
  │
  ▼
底部 Tab Bar "消息" 显示未读角标数字
```

## 6. 功能模块详情

### 6.1 移动首页（待办概览）`/mobile`

#### 6.1.1 页面结构

| 区域 | 内容 | 交互 |
|------|------|------|
| 用户欢迎区 | 头像 + "你好，{姓名}" + 部门 | 静态展示 |
| 统计卡片（2×2） | 待审批 / 今日待跟进 / 逾期提醒 / 未读消息 | 点击跳转对应列表页 |
| 快捷操作（2列） | [新建审批] [新建跟进] | 蓝色主按钮 + 白底次按钮 |
| 待审批列表 | 最新 3 条审批中记录（公司名 + 服务产品 + 状态） | 点击进详情，「全部 →」跳列表 |
| 跟进提醒 | 最新 3 条逾期记录（客户名 + 等级 + 逾期天数） | 点击跳跟进列表 |

#### 6.1.2 数据来源

| 指标 | 数据来源 |
|------|---------|
| 待审批数 | `riskApprovals.filter(status === 'in_review')` |
| 今日待跟进 | `followUps.filter(followUpDate === 今天)` |
| 逾期提醒 | `GET /api/followup-reminders` |
| 未读消息 | `GET /api/notifications?unreadOnly=true` |

#### 6.1.3 加载状态

- 首次加载：显示 `SkeletonList`（骨架屏，4 张卡片）
- 数据为空：显示空状态占位（图标 + 文字 + 操作引导）

### 6.2 审批中心

#### 6.2.1 审批列表 `/mobile/approvals`

**视图**：卡片列表，每卡片显示：状态色条(左) + 公司名 + 服务产品 + 时间 + 状态 Badge

**筛选**：顶部标签横滑 — 全部 / 审批中 / 已完成 / 已驳回 / 草稿

**搜索**：顶部搜索框，按公司名或服务产品搜索

**状态颜色**：

| 状态 | 英文值 | Badge 颜色 |
|------|------|-----------|
| 草稿 | `draft` | 灰色 `#D5D5D5` |
| 审批中 | `in_review` | 蓝色 `#2D3BFF` |
| 已完成 | `approved` | 绿色 `#0D8A5E` |
| 已驳回 | `rejected` | 红色 `#D63031` |

**排序**：按 `updatedAt` 倒序

#### 6.2.2 审批详情 `/mobile/approvals/[id]`

**Section 结构**（竖直堆叠，非 Tab 切换）：

| Section | 内容 |
|---------|------|
| 头部 | 返回按钮 + 公司名 + 当前状态 + StatusBadge |
| 基本信息 | 公司全称、英文名称、集团母公司、分子公司 |
| 关联信息 | 服务产品、关联商机、结算账期、联系人 |
| 业务信息 | 贸易代理、业务类型、货物类型、月均订单数/开票额、通关/运输/仓储 KPI、定制化服务需求+描述 |
| 合规审核 | 动态字段键值对（如有 `dynamicFieldValues`） |
| 审批流程 | `ApprovalFlowMini` — 6 节点垂直时间线 |
| 审批辅助报告 | `ApprovalReportMini` — 规则名/字段/结果/原因 横滑表格 |
| 操作历史 | 操作人+操作+时间，按时间倒序 |
| 底部操作栏 | 固定底部，根据状态显示不同按钮（见 §4.1） |

**审批辅助报告**：实时调用 `evaluateApprovalRules()`，结果分 pass/warn 两类，显示通过数+风险数。

**操作按钮逻辑**：

| 审批状态 | 按钮布局 |
|---------|---------|
| 草稿 | [发起审批]（全宽蓝色） |
| 审批中 | [撤回]（白底灰字）[驳回]（红色）[通过]（绿色） |
| 已驳回 | [编辑并重新发起]（跳转桌面端） |
| 已完成 | "✅ 审批已完成"（静态文字） |

**安全措施**：
- 驳回需填写理由（空理由时 toast 提示）
- 撤回需二次确认弹窗（ConfirmDialog）
- 所有操作有 sonner toast 反馈

#### 6.2.3 新建审批 `/mobile/approvals/new`

**布局**：分层渐进式 — 6 个 `MobileFormSection` + 审批辅助报告

**字段清单（与桌面端 PRD §5.6 严格对齐）**：

##### 公司信息（默认展开）

## 7. 通用交互规范

### 7.1 移动端布局规范

| 规范项 | 值 | 说明 |
|--------|-----|------|
| 基准字号 | **15px**（桌面端 14px） | 移动端阅读舒适度优先 |
| 输入框字号 | **16px** | 防止 iOS Safari 自动缩放 |
| 最小触控区域 | 重要按钮 **44×44px**，筛选标签等内联元素自然高度（`py-1`） | 操作按钮（提交/通过等）显式 `h-11`=44px；筛选 Chip 不使用全局强制 min-height |
| 内容最大宽度 | 100% | 无 max-w 限制 |
| 卡片圆角 | 12px | 全局统一 |
| 页面内边距 | 16px | `px-4` |
| 底部导航高度 | 56px + safe-area-inset-bottom | 适配 iPhone X+ 刘海屏 |
| 底部操作栏 | `z-40 fixed bottom-0` | padding 含 TabBar + safe-area |
| 安全区域 | `env(safe-area-inset-*)` | 顶部 statusBar + 底部 homeIndicator |

### 7.2 触控与手势

| 交互 | 实现 |
|------|------|
| 点击反馈 | `active:bg-[#F5F5F5]` 所有可点击元素 |
| 下拉刷新 | `PullToRefresh` 组件（touchstart/move/end） |
| 底部 Sheet | `MobileSelectSheet`（从底部滑入，搜索框 16px 字号防 iOS 缩放，不使用 autoFocus） |
| 二次确认 | `ConfirmDialog`（底部弹出，半屏遮罩） |
| 页面转场 | `mobileFadeIn` 动画（fade + translateY 8px） |

### 7.3 表单输入

| 规范 | 说明 |
|------|------|
| 统一控件 | `.mobile-input` / `.mobile-textarea` CSS class |
| 聚焦态 | `focus:border-[#2D3BFF] focus:ring-1` |
| 必填标识 | 红色 `*` 星号 |
| 错误态 | 红色边框 + label 变红 + 错误提示文字 |
| 折叠分区 | `MobileFormSection`，可选字段默认折叠 |
| 提交验证 | 校验所有必填项 → 未填标红 → toast 提示数量 → 自动滚动到第一个错误 |
| 筛选标签 | `rounded-full px-4 py-1` 横向 pill，不使用全局 min-height 强制撑高 |

### 7.4 反馈与通知

| 类型 | 组件 | 场景 |
|------|------|------|
| 操作成功 toast | `sonner` | 审批通过/驳回/撤回、草稿已保存、跟进已保存 |
| 操作失败 toast | `sonner` | 提交失败、网络错误 |
| 确认弹窗 | `ConfirmDialog` | 撤回审批、全部已读、删除操作 |
| 加载骨架屏 | `SkeletonList/SkeletonDetail` | 首页加载、审批列表加载 |
| 空状态 | 图标 + 标题 + 描述 | 列表无数据时 |

# 国内 MDM 平台调研 —— 用友与金蝶

> 来源：用友 iUAP MDM 官方文档、金蝶 AMDM V7.5 产品文档、公开技术资料  
> 整理日期：2026-06-24

## 1. 金蝶 AMDM（Apusic Master Data Management）

### 1.1 产品定位

金蝶 AMDM V7.5 定位为"集团管控模式下的主数据治理工具"，基于金蝶云-苍穹 PaaS 平台，融合数据资产管理及数据治理架构理论。

### 1.2 总体架构

```
SaaS 应用层（财务云/人力云/供应链云/供应商协同云/制造云...）
       |
PaaS 平台服务层（应用开发/社交服务/大数据服务/AI服务/云基础技术）
       |
主数据中台（AMDM：数据建模/主数据维护/参考数据维护/应用系统维护/数据集成同步/监控告警）
       |
基础设施服务层 IaaS（华为云/AWS/京东云/国产化飞腾/鲲鹏）
```

### 1.3 六大功能模块

| 模块 | 功能 |
|------|------|
| **数据建模** | 主数据模型、应用系统模型、参考数据模型，支持动态创建和版本化 |
| **主数据维护** | 全生命周期：新增→提交→审核→变更→启用/禁用→历史追溯→分发 |
| **参考数据维护** | 码表数据（性别、学历、客户类别等） |
| **应用系统维护** | 外部系统私有属性补充维护 |
| **主数据集成** | 采集配置 + 分发配置（Push/Pull）+ 调度作业 + 集成日志 + 监控告警 |
| **流程与规则引擎** | BPMN2.0 工作流 + 界面规则 + 业务规则 + 字段校验 + 组合唯一校验 |

### 1.4 对"客商主数据"的处理

金蝶采用**统一 Party 模型**：
- 客户和供应商纳入统一的"客商主数据"管理域
- 集团总部定义公共属性标准（强管控）
- 下级单位在从模型中扩展个性化字段
- 通过**自然语言分词及相似度算法**识别疑似重复客商
- 客户/供应商作为同一"外部交易实体"的不同角色

### 1.5 菜单结构（可直接参考）

```
AMDM 主数据管理平台
├── 数据建模
│   ├── 主数据模型管理
│   ├── 应用系统模型管理
│   └── 参考数据模型管理
├── 主数据维护
│   ├── 客商主数据（客户/供应商统一入口）
│   ├── 物料主数据
│   ├── 人员主数据
│   ├── 组织岗位主数据
│   └── 财务主数据
├── 参考数据维护
│   └── 码表管理
├── 主数据集成
│   ├── 采集配置
│   ├── 分发配置
│   ├── 调度作业
│   └── 集成日志
├── 流程管理
│   └── 工作流配置
├── 监控告警
│   ├── 统计分析卡片
│   └── 预警规则
```

## 2. 用友 MDM（iUAP 主数据管理）

### 2.1 产品定位

用友主数据管理平台（iUAP MDM / 用友云主数据管理 V5.0）面向集团型企业，核心理念：**帮助企业创建并维护跨系统主数据的单一视图**。

### 2.2 分层架构

| 架构层级 | 功能 |
|---------|------|
| 对象层 | 定义主数据实体模型，描述属性及实体间关系 |
| 服务层 | 通用主数据管理服务（CRUD、状态管理、查询、路径维护） |
| 供应层 | 与 ESB 集成，控制主数据传输与分发 |
| 集成层 | ESB + 内容集成器实现异构系统连接、数据清洗、匹配映射 |
| 接口层 | XML、Web Services、实时接口 + 批处理接口 |

### 2.3 "客户"与"主体"的关系

用友采用**分域模型**：

- **客户**：属于"客商域"，代表与企业发生交易的外部组织。支持多角度建模、多源加载、查重合并、编码规则管理。
- **主体（组织）**：属于"主体域"，包含两套架构：
  - 管理架构（HR 系统来源，描述行政层级：集团→公司→部门→岗位）
  - 财务法人架构（财务系统来源，描述法人实体层级）

**关键区分**：客户是"外部单位"，主体是"内部组织"。两者是不同域的主数据。

### 2.4 覆盖的主数据域

6 大类：客户域（客商）、主体域（组织）、人员域、产品域、项目域、财务域

## 3. 两种模型的对比与适用场景

| | 金蝶（统一 Party 模型） | 用友（分域模型） |
|---|---|---|
| 客户/供应商关系 | 统一入口，角色标签区分 | 分属不同域，各自独立 |
| 适用场景 | 客商重叠度高、需要 360 视图 | 各业务线独立、角色边界清晰 |
| 优势 | 避免重复录入，统一视图 | 治理边界清晰，各域独立 |
| 劣势 | 治理流程复杂 | 可能存在重复 |

## 4. 对 CIM2.0 的启示

1. **金蝶的菜单结构可以直接参考**：主数据维护 → 客商主数据 → 按角色标签筛选
2. **用友的"主体域"设计值得借鉴**：CIM 的"服务主体/签约主体/结算主体"类似于用友的主体域双重架构
3. **两者都使用了工作流引擎**：地址新增/修改如果未来需要审批，可以借鉴 BPMN2.0 工作流模式
4. **重复识别机制**：金蝶的 NLP 相似度算法可用于 CIM 的重复地址/重复主体检测

## 二、地址主数据 — 详细设计

### 2.1 设计目标

地址主数据从服务主体的深层嵌套中独立为一级菜单，提供**跨客商、跨主体、跨收发货方**的全局地址视图。地址解析由高德地图 API 自动完成，省市区和经纬度不允许人工直接修改。

### 2.2 数据模型（已实现）

```
service_entity (服务主体·已有)
  └── shipper_consignee (收发货方)
       ├── id, service_entity_id, name, code, type, uscc
       ├── contact_person, phone, email
       └── status, remark, created_at, updated_at
            │
            └── address_site (地址站点)
                 ├── id, shipper_consignee_id, service_entity_id (冗余)
                 ├── name, code, province, city, district
                 ├── detail_address (必填·解析输入)
                 ├── doorplate (手填), postal_code (手填)
                 ├── longitude (解析带出), latitude (解析带出)
                 ├── geo_accuracy (precise/approximate/manual/unresolved)
                 ├── special_customs_zone (boolean)
                 ├── special_requirements (text)
                 ├── status, version (初始=1)
                 ├── created_at, updated_at
                 │
                 ├── address_usage (地址用途·1:N)
                 │    └── id, address_site_id, usage_type, created_at
                 │         usage_type ∈ {receiving, shipping, pickup, delivery,
                 │                        return, customs, warehousing}
                 │
                 ├── address_contact (地址联系人·1:N)
                 │    └── id, address_site_id, name, phone, email
                 │         is_primary, remark, created_at, updated_at
                 │
                 └── address_version (版本快照·1:N)
                      └── id, address_site_id, version, snapshot(JSON)
                           changed_by, changed_at, change_summary
```

### 2.3 编码规则

| 实体 | 前缀 | 格式 | 示例 |
|------|------|------|------|
| 地址站点 | ADS | `ADS-{YYYYMMDD}-{3位序号}` | `ADS-20260624-001` |
| 收发货方 | SHC | `SHC-{YYYYMMDD}-{3位序号}` | `SHC-20260624-005` |

编码通过 `code_sequences` 表原子递增，跨日自动重置序号。

### 2.4 地址解析流程

1. 用户在"详细地址"输入框填写完整地址
2. 输入框 blur 时自动调用 `POST /api/address-resolve`（高德 geocoding API）
3. 解析成功 → 省市区下拉框自动选中、经纬度只读字段自动填充、精度标记为 precise/approximate
4. 解析失败 → toast 提示"地址解析失败，请手动填写省市区信息"，精度标记为 unresolved，允许手填
5. 若解析结果错误 → 用户修改"详细地址"文本后点击"重新解析"按钮
6. 省、市、区、经纬度字段**不允许人工直接修改**，只能由解析服务填充

### 2.5 全局地址列表页

独立页面，路由 `/addresses`。列表字段：

| 列 | 说明 |
|----|------|
| 地址编码 | ADS 编码（可点击进入详情） |
| 站点名称 | 地址站点名称 |
| 完整地址 | 省+市+区+详细地址（拼接） |
| 所属客商 | 通过 service_entity_id 关联到客商名称 |
| 收发货方 | 所属收发货方名称 |
| 用途标签 | 收货/发货/提货/... 标签列表 |
| 联系人 | 首位联系人姓名+电话 |
| 解析状态 | 未解析/解析成功/解析失败 |
| 状态 | 启用/停用 |
| 操作 | 查看 · 编辑 · 停用 |

## 三、产业链主数据 — 详细设计

### 3.1 设计定位

产业链主数据是一个**独立的主数据域**，和地址主数据一样，作为一级菜单存在。它存储客商之间的供应链关系（谁供应谁、谁代工谁、谁经销谁）。首期只做列表页的增删改查，不建设可视化图谱。

### 3.2 数据模型

```sql
chain_relationship (
  id              TEXT PRIMARY KEY,    -- 如 chr-{timestamp}
  from_customer_id TEXT NOT NULL,     -- 来源客商ID（上游）
  to_customer_id   TEXT NOT NULL,     -- 目标客商ID（下游）
  relation_type    TEXT NOT NULL,     -- supply(供应) / manufacturing(代工) / distribution(经销) / service(服务)
  chain_level_from TEXT,             -- 来源端产业链层级：upstream/midstream/downstream
  chain_level_to   TEXT,             -- 目标端产业链层级
  chain_role_from  TEXT,             -- 来源端产业链角色：equipment_supplier/foundry/osat/...
  chain_role_to    TEXT,             -- 目标端产业链角色
  is_direct        INTEGER DEFAULT 1, -- 是否直接关系
  effective_date   TEXT,             -- 生效日期
  expiry_date      TEXT,             -- 失效日期（可为空 = 长期有效）
  remark           TEXT,             -- 备注
  status           TEXT DEFAULT 'active', -- active/inactive
  created_at       TEXT,
  updated_at       TEXT
)
```

### 3.3 编码

产业链关系不单独编码。以 `from_customer_id + relation_type + to_customer_id` 组合作为业务唯一键。

### 3.4 产业链关系列表页

独立页面，路由 `/chain-relationships`。

| 列 | 说明 |
|----|------|
| 来源客商 | from_customer 名称（可点击跳转至客商详情） |
| 关系类型 | 供应 / 代工 / 经销 / 服务 |
| 目标客商 | to_customer 名称（可点击跳转至客商详情） |
| 来源层级 | 上游-设备供应商 / 中游-晶圆厂 / ... |
| 目标层级 | 下游-终端厂商 / ... |
| 生效日期 | effective_date |
| 状态 | 生效 / 失效 |
| 操作 | 查看 · 编辑 · 停用 |

筛选条件：来源客商、目标客商、关系类型、产业链层级。

### 3.5 产业链关系详情页

路由 `/chain-relationships/[id]`。

- 来源客商卡片：名称、产业链层级、产业链角色、统一社会信用代码 → [跳转至客商详情]
- 关系卡片：关系类型（大标签）+ 方向箭头（→）+ 是否直接关系
- 目标客商卡片：名称、产业链层级、产业链角色、统一社会信用代码 → [跳转至客商详情]
- 元数据：生效日期 · 失效日期 · 状态 · 备注

### 3.6 远期扩展（不在本期范围）

- 产业链可视化图谱（力导向图/桑基图）
- 链条覆盖度分析（哪些产业链环节有客户、哪些空白）
- 风险传导分析（上游停产影响下游交付）
- 交叉销售机会识别（为上游客户推荐下游物流服务）

## 四、客商管理 — 详细设计

### 4.1 改名缘由

"客户管理"改名为"客商管理"，为未来扩展供应商角色预留空间。参考金蝶 AMDM 的"客商主数据"命名，一个客商可同时是客户和供应商。

### 4.2 详情页 Tab 详解

| Tab | 功能 | 数据来源 |
|-----|------|---------|
| 基本信息 | name, customer_code, uscc, status, created_at | customers 表 |
| 业务档案 | level(K/A/B/C/D), industry, service_products, responsible_persons, progress_status | customers 表 |
| **产业链定位** | chain_level(上游/中游/下游), chain_role(设备供应商/晶圆厂/...) | customers 表新增字段 |
| **组织架构** | 集团→子公司→部门 树形结构 | customer_org_structure 表 |
| **关联主体** | 列出签约/服务/结算主体，点击跳转至主体管理 | entity_ids + USCC 关联 |
| **联系人** | 按 contact_type 分类：客户/商务/财务/关务/现场 | contacts 表（扩展 contact_type） |
| 地址与收发货 | 关联的收发货方+地址站点列表（快捷查看） | shipper_consignee + address_site |

### 4.3 产业链定位字段

客商编辑表单"业务档案"卡片中新增两个下拉框：

| 字段 | 字段Key | 可选值 |
|------|---------|--------|
| 产业链层级 | chain_level | 上游(upstream) / 中游(midstream) / 下游(downstream) |
| 产业链角色 | chain_role | 设备供应商 / 材料供应商 / IP提供商 / EDA厂商 / 晶圆代工厂(Foundry) / 芯片设计(Fabless) / IDM / 封装测试(OSAT) / SIP / 分销商 / 系统集成商 / 终端厂商 / 其他 |

### 4.4 组织架构

新增 `customer_org_structure` 表，自引用层级：

```
customer_org_structure (
  id          TEXT PK,
  customer_id TEXT NOT NULL,       -- 所属客商
  parent_id   TEXT,                -- 父节点（自引用FK，根节点=null）
  org_name    TEXT NOT NULL,       -- 组织名称
  org_type    TEXT,                -- 集团/子公司/事业部/部门/工厂/仓库
  level       INTEGER DEFAULT 0,   -- 层级深度
  status      TEXT DEFAULT 'active',
  created_at  TEXT, updated_at TEXT
)
```

客商详情页"组织架构"Tab 中以树形组件展示：集团 → 子公司 → 事业部 → 部门。

### 4.5 联系人扩展

现有 `contacts` 表新增字段 `contact_type`：

| 类型 | 值 | 说明 |
|------|----|------|
| 客户联系人 | customer | 现有 contacts 记录默认值 |
| 商务联系人 | business | 商务合作对接 |
| 财务联系人 | finance | 结算/开票对接 |
| 关务联系人 | customs | 报关资料对接 |
| 仓储联系人 | warehouse | 出入库对接 |
| 运输联系人 | transport | 运输调度对接 |
| 现场联系人 | site | 地址级联系人（address_contacts 表单独管理） |

## 五、客商 ⇄ 主体 双向关联设计

### 5.1 关联原理

客商和主体通过**统一社会信用代码（uscc）**自动关联。同一法律实体在客商表和主体表中共享相同的 uscc。

### 5.2 页面交互

```
客商详情页                             主体详情页
┌────────────────────┐    ┌────────────────────┐
│ 应用材料(中国)       │    │ 应用材料(中国)       │
│ uscc: 9131...      │    │ uscc: 9131...      │
│                    │    │ 角色: [签约][服务]   │
│ [关联主体] Tab      │    │                    │
│ ┌────────────────┐ │    │ [关联客商] Tab      │
│ │ 签约主体 → 点击  │ │    │ ┌────────────────┐ │
│ │ 服务主体 → 点击  │ │    │ │ 客商记录 → 点击  │ │
│ └────────────────┘ │    │ └────────────────┘ │
└────────────────────┘    └────────────────────┘
         ⇄ USCC 自动关联 ⇄
```

- 后端：根据 uscc 查询关联关系，返回双方 ID
- 客商详情"关联主体"Tab：列出 uscc 匹配的主体记录，点击跳转
- 主体详情"关联客商"Tab：列出 uscc 匹配的客商记录，点击跳转
